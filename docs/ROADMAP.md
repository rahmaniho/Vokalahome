## بدهی فنی

مواردی که الان مشکلی ایجاد نمی‌کنند ولی باید حواسمان باشد:

| # | مورد | ریسک | چه وقت |

| ب۲ | بدون آزمون خودکار | رگرسیون ممکن است دیده نشود | پیش از فاز ۳ |
| ب۳ | تصاویر در مخزن git | مخزن بزرگ می‌شود (الان ۵٫۴MB — بی‌خطر) | بالای ۵۰MB |
| ب۴ | بدون گزارش خطای تولید | خطای کلاینت کاربران دیده نمی‌شود | وقتی ترافیک زیاد شد |
| ب۵ | نسخهٔ Pannellum قفل روی CDN | اگر jsDelivr قطع شود، تور ۳۶۰ کار نمی‌کند | خودمیزبانی، ۱ ساعت |

### پیشنهاد برای ب۱ و ب۲

**ب۱ — CMS:** اگر روزی لازم شد، [Decap CMS](https://decapcms.org/) (سابق Netlify CMS)
روی همین GitHub Pages کار می‌کند: یک فایل پیکربندی، ورود با حساب گیت‌هاب، و محتوا
مستقیم در مخزن commit می‌شود. بدون سرور.

**ب۲ — آزمون:** حداقل کار مفید، یک تست دود با Playwright که ۵ صفحهٔ اصلی را باز کند
و بررسی کند چیزی نشکسته. حدود ۲ ساعت کار، و جلوی بیشتر رگرسیون‌ها را می‌گیرد.

۳. **چقدر به بودجهٔ کارایی اضافه می‌کند؟** سقف‌ها در [`PERFORMANCE.md`](PERFORMANCE.md#۵-بودجهٔ-کارایی).
